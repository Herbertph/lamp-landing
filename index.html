From a wish to a pull request

  1. You make the wish

    Write what you want, the way you would say it to a colleague. No prompts, no terminal.

  2. The Analyst writes the spec

    It asks you when something is unclear, then writes requirements with numbered acceptance criteria.

  3. The Developer builds it

    On its own branch, in the style your code already uses, with tests next to the change.

  4. QA tests everything

    Test cases, Playwright automation and a code review. Every failure becomes a GitHub issue and goes back to the Developer until it passes.

  5. You approve one pull request

    Nothing reaches you until QA says it is ready. Read it, approve it, done.

Many wishes at once

Each task gets its own team and its own copy of the code, so a feature and a quick fix can run side by side.
